## 🤖 CAPTCHAとは？

**CAPTCHA（Completely Automated Public Turing test to tell Computers and Humans Apart）**は、人間とコンピュータープログラムを区別するための自動テストです。

### CAPTCHAの基本概念

- **目的**: 人間には簡単だが、機械（bot）には困難なタスクを提供すること
- **原理**: 人間の認知能力（文字認識、パターン認識など）を活用
- **用途**: スパムやDDoS攻撃の防止、不正アクセスの阻止

### 従来型CAPTCHAの仕組み

1. **文字の歪み**: 文字を波形で歪ませることで、OCRソフトの認識を困難にする
2. **ノイズの追加**: 背景にランダムな点や線を追加し、文字境界を曖昧にする
3. **色の変化**: 文字と背景のコントラストを調整し、自動認識を妨害する

### 現代の課題

- **機械学習の進歩**: 深層学習技術により、従来型CAPTCHAは容易に突破される
- **アクセシビリティ**: 視覚障害者や高齢者にとって利用困難
- **ユーザビリティ**: 人間にとっても読みにくく、ユーザー体験を損なう

### CAPTCHAとセキュリティの関係

CAPTCHAは**多層防御戦略**の重要な一部として位置づけられます。

- **第一防衛線**: 自動化されたbot攻撃の大部分を阻止
- **リソース保護**: サーバーリソースやデータベースへの過負荷を防止
- **データ品質維持**: スパムやフェイクアカウントの大量作成を抑制
- **コスト削減**: 人的監視やクリーンアップ作業の負担を軽減

しかし、CAPTCHAは**完全なセキュリティ解決策ではありません**。

- **突破可能性**: 高度なOCRや機械学習により解読される可能性
- **人的解決**: 低コストの人的労働によって突破される場合
- **ユーザビリティとの競合**: 強固にするほど正当なユーザーにも負担

### 現代のセキュリティ対策との統合

現在の最適解は、CAPTCHAを含む**多要素セキュリティアプローチ**です。

1. **リスクベース認証**: ユーザーの行動パターン分析
2. **レート制限**: API呼び出しやアクセス頻度の制御
3. **デバイスフィンガープリンティング**: 端末特徴による識別
4. **二要素認証（2FA）**: SMS、アプリ、ハードウェアキーとの組み合わせ
5. **行動分析**: マウス移動、タイピングパターンの解析

### 本ツールの教育価値

このツールを通じて、CAPTCHAの「人間には読めるが機械には読みにくい」という理想と現実のギャップを体感し、現代のセキュリティ対策における多層防御の重要性を理解できます。
セキュリティは単一の技術に依存するのではなく、複数の手法を組み合わせた総合的なアプローチが必要であることを学習できます。

## 🔧 仕様

- **入力と出力**
  - テキストを入力すると、CAPTCHA風に歪ませた画像を生成
  - PNG/SVG形式で保存可能
  - ランダムシード固定により同条件での再現が可能

- **プリセットモード**
  - Classic: 軽い波形と細線を加えた標準的CAPTCHA風
  - Elastic: 強めの非線形ワープ
  - Grainy: 粒子ノイズや紙目風の質感
  - Chaotic: 線や点群を多用した難読化
  - Minimal: ほぼ加工なし（比較用）

- **スライダー調整**
  - 波形の振幅・周波数
  - 文字間隔・回転ばらつき
  - 前景/背景コントラスト
  - ノイズの密度や線の太さ・本数
  - ぼかし量

- **可読性スコア**
  - Human Readability (HR): 人間が文字を判読できるかを示す 0-100 スコア。前景の占有率、ノイズによる視認性の低下、文字ストロークが連続しているかを指標化
  - Bot Readability (BR): OCR が読み取れるかを推定する 0-100 スコア。輪郭の明瞭さ、占有率、水平エッジ遷移の少なさを基に算出
  - 各メーターにはヘルプアイコン付きで詳細説明を提供
  - HRとBRをゲージ表示し、調整の影響を即時に可視化

- **分解ビュー**
  - レイヤーごとに処理の段階をアニメーション表示
  - 下地 → 文字描画 → ワープ → ノイズ → 線 → 完成、の流れを学習可能

## 📊 教育的な有効性と限界

- **体感的に学べる**
  - スライダーを少し動かすだけでHR/BRの変化が可視化されるため、  
    「読みやすさ」と「機械耐性」のトレードオフを直感的に理解できる。
- **加工の種類と効果**
  - 波形や線の追加がOCRにどの程度効くのかを確認できる。
  - 同時に「やりすぎると人間にも読めなくなる」という設計の難しさも体験可能。
- **限界の認識**
  - 本ツールのBR/HRスコアはヒューリスティックに基づく推定値であり、  
    実際の機械学習ベースのOCR精度とは一致しない。
  - 近年のディープラーニング技術に対しては従来型CAPTCHAは容易に突破されることを理解するきっかけとなる。
- **次の学習への橋渡し**
  - 「画像CAPTCHA単独では不十分」という気づきから、  
    多要素認証やリスクベース認証の重要性に話を広げられる。
- **倫理的配慮**
  - 本ツールは教育・研究用途に限り利用すること。  
    実運用のセキュリティ対策として使うことは推奨されない。

## 📚 学習シナリオ（推奨手順）

本ツールを効果的に活用するための段階的な学習手順をご紹介します。

### 1. 基本操作：任意のテキストで体験してみる

**目的**: CAPTCHAの基本的な仕組みを理解する

**手順**:
- テキスト入力欄に好きな文字列（名前、メッセージなど）を入力
- プリセットモードを「Classic」→「Elastic」→「Chaotic」と切り替え
- それぞれのモードで画像がどう変化するかを観察
- 「Minimal」モードと他のモードを比較して歪みの効果を確認

**学習ポイント**: 「人間には読めるが機械には読みにくい」の実現がいかに困難かを体感

### 2. パラメーター調整：各項目の効果を個別に確認

**目的**: 各加工要素がCAPTCHA画像に与える影響を理解する

**手順**:
- 一度に1つのスライダーだけを操作し、変化を観察
- 「波形 振幅」を最小→最大に変化させ、文字の歪み具合を確認
- 「ノイズ密度」を調整して、背景ノイズの影響を体験
- 「線の本数」で交差線がどの程度文字を隠すかを確認
- 「コントラスト」で読みやすさがどう変わるかを観察

**学習ポイント**: 個々の要素が視認性と機械認識に与える影響の違いを理解

### 3. レイヤー分解：処理段階ごとの変化を追跡

**目的**: CAPTCHA生成の処理プロセスを段階的に理解する

**手順**:
- 「レイヤー分解」セクションを展開し、7つの処理段階を確認
- レイヤー1（背景）: 「背景の明度」「粒子密度」を変更し、レイヤー1プレビューの変化を観察
- レイヤー2（文字描画）: 「回転ばらつき」「字間」を調整し、レイヤー2の変化を確認
- レイヤー3（ワープ）: 「波形 振幅」「波形 周期」でレイヤー3の歪み変化を観察
- レイヤー4-7の各段階でも同様に対応するパラメーターを調整

**学習ポイント**: 複雑な画像処理が段階的に積み重なってCAPTCHAが完成することを理解

### 4. 可読性分析：HRとBRの関係を探る

**目的**: 人間と機械の読みやすさのトレードオフを定量的に理解する

**手順**:
- HR・BRメーターの「?」アイコンをクリックし、算出方法の説明を確認
- HR（Human Readability）とBR（Bot Readability）の数値を常に確認
- 「コントラスト」を下げてHRの変化を観察（人間にも読みにくくなる）
- 「ノイズ密度」や「線の本数」を増やしてBRへの影響を確認
- 「波形 振幅」を強くしてHR・BR両方への影響を比較
- HRを高く保ちながらBRを下げる組み合わせを探してみる
- 逆にHR・BR両方が下がりすぎる設定も試し、「やりすぎ」を体験

**学習ポイント**: 理想的なCAPTCHAの実現が困難で、現実的には妥協が必要であることを理解
